## 1️⃣ Линейный поиск → мотивация бинарного поиска (8 минут)

### Линейный поиск (в общих словах)

Без кода, только идея:

- идём по элементам по одному;
    
- сравниваем с целевым значением;
    
- в худшем случае — проверяем всё.
    

### Сложность

- время: **O(n)**
    
- память: **O(1)**
    

### Ограничения линейного поиска

Проговорить:

- что если `n = 1 000 000`?
    
- что если поиск нужно делать много раз?
    
- что если данные **отсортированы**?
    

👉 **Переход:**

> Если данные отсортированы, мы можем делать лучше, чем проверять всё подряд.

---

## 2️⃣ Интуиция бинарного поиска (10 минут)

### Концептуальное объяснение

> Бинарный поиск каждый шаг **выбрасывает половину пространства поиска**.

Пример **без кода**:

- угадывание числа от 1 до 100;
    
- вопрос: «больше или меньше 50?»
    

### Ключевая идея

- не ищем ответ напрямую;
    
- **сужаем пространство поиска**.
    

### Сложность

- линейный: O(n)
    
- бинарный: **O(log n)**
    

👉 Важно проговорить:

- log n — растёт **очень медленно**;
    
- бинарный поиск — один из самых мощных приёмов в алгоритмах.
    

---

## 3️⃣ Почему бинарный поиск сложно писать без ошибок (7 минут)

Этот блок — **очень важный**.

### Типичные проблемы:

- `left < right` или `left <= right`?
    
- `mid = (l + r) // 2` или иначе?
    
- `left = mid` или `mid + 1`?
    
- где выход из цикла?
    

### Ключевая мысль

> Большинство ошибок — не из-за идеи, а из-за **границ и условий**.

👉 Вывод:

- нам нужен **универсальный шаблон**;
    
- и главное — **понять логику**, а не заучить код.

## 4️⃣ Бинарный поиск как “поиск минимального k” (12 минут)

### Главная идея

Практически все задачи бинарного поиска можно привести к форме:

> **Найти минимальное k, такое что `condition(k) == True`**

### Обсудить:

- что такое **пространство поиска**:
    
    - массив;
        
    - диапазон чисел;
        
    - ответ задачи.
        
- что такое **монотонность**:
    
    - False, False, False, True, True, True
        

👉 Очень важно:

> Если есть монотонность — почти всегда можно применить бинарный поиск.

## 5️⃣ Базовые применения (easy) — демонстрация и совместная практика (15 минут)

### 🧩 Задача 1 — демонстрация

**LeetCode 278. First Bad Version**

Фокус:

- пространство поиска — версии `[1…n]`;
    
- условие уже есть (`isBadVersion`);
    
- задача = найти **первый True**.
    

Проговорить:

- left / right;
    
- mid;
    
- почему `right = mid`, а не `mid - 1`.
    

```Problem

Вы являетесь менеджером по продукту и в настоящее время возглавляете команду по разработке нового продукта. К сожалению, последняя версия вашего продукта не прошла проверку качества. Поскольку каждая версия разрабатывается на основе предыдущей, все версии после неудачной версии также являются плохими.

Предположим, у вас есть n версий [1, 2, ..., n], и вы хотите найти первую плохую, которая приводит к тому, что все последующие становятся плохими.

Вам предоставляется API bool isBadVersion(версия), который возвращает, является ли версия плохой. Внедрите функцию для поиска первой неудачной версии. Вам следует свести к минимуму количество обращений к API.

Example 1:
Input: n = 5, bad = 4
Output: 4
Explanation:
call isBadVersion(3) -> false
call isBadVersion(5) -> true
call isBadVersion(4) -> true
Получается, что 4 - первая плохая версия

Example 2:
Input: n = 1, bad = 1
Output: 1

1 <= bad <= n <= 2^31 - 1

```

```Solution

def firstBadVersion(self, n) -> int:
	left, right = 1, n
	while left < right:
		mid = left + (right - left) // 2
		if isBadVersion(mid):
			right = mid
		else:
			left = mid + 1
	return left

```

### 🧩 Задача 2 — совместно

**LeetCode 35. Search Insert Position**

Фокус:

- ищем минимальный индекс, где `nums[i] >= target`;
    
- массив может не содержать target;
    
- почему `right = len(nums)`.
    

Обязательно:

- проговорить тест-кейсы;
    
- отдельно обсудить случай, когда `target` больше всех элементов.
    


```Problem

Получив отсортированный массив различных целых чисел и целевое значение, верните индекс, если цель найдена. Если нет, верните индекс в том месте, где он был бы, если бы он был вставлен по порядку.

Необходимо написать алгоритм со сложностью выполнения O(log n).

Example 1:
Input: nums = [1,3,5,6], target = 5
Output: 2

Example 2:
Input: nums = [1,3,5,6], target = 2
Output: 1

Example 3:
Input: nums = [1,3,5,6], target = 7
Output: 4

1 <= nums.length <= 10^4
-10^4 <= nums[i] <= 10^4
nums contains distinct values sorted in ascending order.
-10^4 <= target <= 10^4

```

```Solution

def searchInsert(self, nums: List[int], target: int) -> int:
	left, right = 0, len(nums)
	while left < right:
		mid = left + (right - left) // 2
		if nums[mid] >= target:
			right = mid
		else:
			left = mid + 1
	return left

```

```

There is an integer array nums sorted in ascending order (with distinct values).

Prior to being passed to your function, nums is possibly left rotated at an unknown index k (1 <= k < nums.length) such that the resulting array is [nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]] (0-indexed). For example, [0,1,2,4,5,6,7] might be left rotated by 3 indices and become [4,5,6,7,0,1,2].

Given the array nums after the possible rotation and an integer target, return the index of target if it is in nums, or -1 if it is not in nums.

You must write an algorithm with O(log n) runtime complexity.

Example 1:
Input: nums = [4,5,6,7,0,1,2], target = 0
Output: 4

Example 2:
Input: nums = [4,5,6,7,0,1,2], target = 3
Output: -1

Example 3:
Input: nums = [1], target = 0
Output: -1

```

```

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums)
        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] >= nums[0]:
                left = mid + 1
            else:
                right = mid
        
        pivot = left

        if target >= nums[0]:
            left, right = 0, pivot
        else:
            left, right = pivot, len(nums)
        
        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] > target:
                right = mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                return mid
        
        return -1

```

```

You are given an m x n integer matrix matrix with the following two properties:

Each row is sorted in non-decreasing order.
The first integer of each row is greater than the last integer of the previous row.
Given an integer target, return true if target is in matrix or false otherwise.

You must write a solution in O(log(m * n)) time complexity.

Example 1:
Input: matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 3
Output: true

Example 2:
Input: matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 13
Output: false

```

```

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        left = 0
        right = len(matrix) * len(matrix[0]) - 1

        cols_amount = len(matrix[0])

        while left < right:
            mid = left + (right - left) // 2

            row = mid // cols_amount
            col = mid % cols_amount

            if matrix[row][col] >= target:
                right = mid
            else:
                left = mid + 1

        row = left // cols_amount
        col = left % cols_amount
        return True if matrix[row][col] == target else False


```
